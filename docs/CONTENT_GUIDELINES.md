# Disney Discovery — コンテンツ制作ガイドライン

## 1. 読者と文章
- **メインターゲットはディズニー初心者**。初めて来園する人、久しぶりに来園する人が、準備や当日の行動で迷わないように説明する。
- サブターゲットはライト層、キャラクターや映画に興味を持ち始めた人、検索で疑問を調べている人。
- 初心者・ライト層を想定し、平易で自然な日本語を使う。
- 文体はBGS Chroniclesに合わせ、落ち着いた編集記事の口調に統一する。親しみやすさは保ちつつ、幼児向けの呼びかけ（「きみ」「ぼく」）、過度な感嘆符、幼い擬音・語尾、絵本風の語りかけは避ける。
- 読者に直接呼びかけすぎず、情報を整理して伝える。キャッチコピーも子ども向けにせず、簡潔で自然な表現にする。
- 冒頭で質問への答えを示し、詳細は順序立てて説明する。
- 見出しと本文を一致させ、誇張したクリック誘導をしない。
- 同じ説明の繰り返しや、内容と無関係な文言を入れない。
- 不明なことは不明とし、推測を事実のように書かない。

## 2. 事実確認と出典
- 運営時間、料金、制度、アプリ機能、イベント等の変動情報は、公開前に公式の最新情報を確認する。
- 公式サイト・公式発表・作品本編などの一次情報を優先する。
- 重要な事実、数値、歴史的な説明には出典を付け、読者が確認できる形にする。
- ファンの解釈や未確認の説は、公式設定と明確に区別する。
- 公開日・更新日は、実際に公開・更新した日付と一致させる。

## 3. 著作権・商標・画像
- 公式画像、映画の静止画、ロゴ、他サイトの写真や文章を、許諾や適法な利用根拠なしに転載しない。
- 引用する場合は、適用される法令・引用要件を確認し、必要最小限にとどめ、出典を明記する。
- 画像は自作、適切なライセンスが確認できる素材、または利用許諾を得たものを優先する。
- ディズニー公式の情報メディアであるかのような誤認を招かない。非公式メディアとしての表示方法もサイト公開前に検討する。

## 4. SEO・独自性
- 検索語を不自然に詰め込まない。
- SEOの第一優先は、初心者が実際に抱く疑問と検索意図への回答。タイトル・導入・見出し・本文・descriptionは自然な日本語で一貫させる。
- 「初心者」「初めて」などの語句は記事の内容に合う場合だけ使い、全ページに機械的に付けない。
- 初心者向けの用語説明と、詳しい読者向けの補足を分け、読者が必要な情報を見つけやすくする。
- 既存記事の言い換えや、他サイトの構成をなぞっただけの記事を作らない。
- 読者に役立つ整理、説明、比較、具体例を加える。
- タイトル・見出し・本文・メタ情報の内容を揃える。
- 記事間の重複を避け、必要に応じて統合・内部リンクを検討する。

## 5. 公開前チェック
- [ ] 検索者の疑問に明確に答えている
- [ ] タイトル・見出しと本文の内容が一致している
- [ ] 固有名詞、日付、数値、制度を確認した
- [ ] 出典・リンクが正しく、主張を支えている
- [ ] 推測と事実を区別した
- [ ] 著作権・画像利用を確認した
- [ ] 誤字脱字、重複、関係のない文言がない
- [ ] スマートフォンでも読みやすい
- [ ] 内部リンク・共有プレビュー等は実装後に動作確認した

## 6. 更新ルール
変更が必要な情報を見つけたら、本文・更新日・必要な関連箇所をまとめて確認する。更新していないのに更新日だけを変更しない。

## 7. ブランドの語り口（2026-10-12追記）
- 企業の広報文・サービス紹介のような大げさな言い回しを避ける。
- 「もっと深く、もっと身近に」「景色が変わる」「確かな手がかり」など、サイト自身を必要以上に格好よく見せる抽象的なコピーを多用しない。
- 読者に上から教える口調や、運営者のこだわりを過度に語る自己紹介を避ける。何を扱うサイトかを具体的に短く説明する。
- 親しみやすさは、幼い口調や過剰な装飾ではなく、自然な日本語と具体例で出す。
- 見出しやボタンは短く、内容が一目でわかる言葉にする（例：「記事を読む」「このサイトについて」「パークの豆知識」）。


## 9. 文体の統一（2026-10-14追記）
- サイト内の解説本文は、自然で読みやすい標準語の「です・ます」調を基本とする。
- 「だ・である」調、くだけた口語、幼い語尾、過度な読者への呼びかけ、不要な感嘆符を同じ記事内・記事間で混在させない。
- 親しみやすさは、語尾を崩すのではなく、具体例・簡潔な説明・自然な語彙で表現する。
- 企業の広報文のような大げさな表現や、子ども向けの過剰にやさしい語り口は避ける。落ち着いた編集記事として、読者に敬意を払いつつ端的に説明する。
- 見出しは内容がすぐ伝わる自然な標準語にする。見出し自体は体言止めでもよいが、本文の文体と混同しない。
- キャラクターのセリフ、作品名、慣用句など、引用・固有表現として必要な箇所は機械的に書き換えない。
- 文体統一の編集では、事実関係、記事の主張、情報量、リンク、SEOメタ情報を意図せず変更しない。文体変更に伴ってタイトルや要約の不自然さが生じる場合だけ、整合性を確認する。

## 8. 画面の見せ方・正確性の伝え方（2026-10-12追記）
- 角丸のない四角いパネルを連続させず、カード・ラベル・ボタンに適度な丸みを持たせる。ただし、丸い箱を増やしすぎず余白と見出しで整理する。
- トップページに全記事を並べない。入口としてテーマの異なる記事を少数だけ見せ、残りは記事一覧やカテゴリから探せるようにする。
- 正確性のための確認は編集側で徹底するが、「公式情報をもとに」「確認日」などの注記を一覧で何度も繰り返して、堅い印象にしない。必要な注意書きは記事本文の該当箇所に自然に置く。
- 料金・運営時間・制度など、誤解すると困る変動情報は本文中で確認先や更新時点を示す。背景雑学や読み物にまで、同じ調子の確認ラベルを一律に付けない。

## 10. 実用性を最優先する編集方針（2026-10-27追記）
- Disney Discoveryは、歴史や背景設定を深掘りすること自体ではなく、読者がパークを便利に・自分らしく楽しむための判断材料を提供する。
- 記事の中心は「どこで見るか」「いつ動くか」「何を準備するか」「どちらを選ぶか」「予定が崩れたらどうするか」など、実際の行動に結びつく疑問とする。
- 冒頭で、読者が知りたい結論やおすすめの考え方を先に示す。記事の前半で「結局どうすればいいか」がわかる構成にする。
- 「公式によると」「公式情報をもとに」などの定型句を段落ごとに繰り返さない。公式情報は編集側の事実確認に使い、本文では読者にとって必要な条件・例外・確認方法を自然に説明する。
- 料金、利用条件、開催時刻、運営状況など、誤解すると困る変動情報は必要な箇所で確認先や更新時点を示す。すべての段落に確認ラベルを付けない。
- 便利さを具体化する。一般論だけで終わらせず、比較表、行動手順、目的別の選び方、代替案、当日確認する項目などを必要に応じて加える。
- 体験談・傾向・編集上の提案を、公式発表で確認できる事実と混同しない。独自の実測をしていない待ち時間などは断定せず、「目安」「傾向」「当日の状況による」と条件を明示する。
- 待ち時間や場所取り時間を示す場合、万能の正解のように断言しない。曜日、繁忙期、鑑賞位置、希望する見え方など、目安が変わる条件を説明する。
- 記事を長くするためだけの繰り返しを避ける。文字数ではなく、読者の疑問を解決するために必要な情報が揃っているかで完成度を判断する。
- BGS Chroniclesとの役割を分ける。DDは実用情報・攻略・選び方を中心にし、背景設定や物語の深掘りは必要に応じてBGS Chroniclesへ案内する。
- 公開前には「読者がこの記事を読んだあと、具体的に何を決めたり実行したりできるか」を確認する。答えが曖昧なら、実用的な情報を補う。
