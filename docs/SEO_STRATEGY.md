# Disney Discovery — SEO・記事戦略

## 1. 基本方針
検索流入を最優先にする。ただし、検索語を含めるだけの記事ではなく、読者の疑問に正確かつ簡潔に答え、必要な補足まで提供する。

## 2. メインターゲットと検索意図

### メインターゲット
- **ディズニー初心者**：東京ディズニーリゾートへ初めて行く人、久しぶりに行く人、チケット・アプリ・当日の回り方などの基本を知りたい人。
- **サブターゲット**：年に数回程度パークを楽しむライト層、ディズニー映画やキャラクターに興味を持ち始めた人、検索やSNSで見かけた疑問を確かめたい人。

記事企画とSEO改善では「ディズニー初心者が、来園前や当日に困ることを解決する」を優先する。ただし、すべての記事を初心者向けに無理に寄せず、キャラクターや映画の雑学はその検索意図に合わせて制作する。

### 優先する検索意図・キーワード群
- **来園準備**：「ディズニー 初めて」「ディズニー 初心者」「ディズニー 持ち物」「ディズニー 服装」
- **天候・季節**：「ディズニー 雨の日」「ディズニー 暑さ対策」「ディズニー 冬 持ち物」
- **チケット・アプリ**：「ディズニー チケット 買い方」「ディズニー アプリ 使い方」「スタンバイパス 違い」
- **当日の過ごし方**：「ディズニー 回り方 初心者」「ディズニー 子連れ 準備」「ディズニー 予算」
- **基礎知識・雑学**：「ディズニーランド シー 違い」「キャラクター 名前・見分け方」など、具体的な疑問に対応する語句
- **パークの背景設定・用語**：「BGSとは」「ディズニー BGS 意味」「バックグラウンドストーリーとは」など、パークの作り込みや背景設定に興味を持ち始めた読者向けの語句。BGSが何の略か、パークでどのような意味で使われるかを初心者にもわかるように説明する。

上記は編集上の仮説であり、検索ボリュームや競合性を調査していない語句について需要が高いと断定しない。Search Consoleのデータが蓄積したら、実際の検索語に基づいて優先順位を更新する。

## 3. 記事候補を評価する基準
各候補を、公開前に次の観点で確認する。
- **検索需要:** 実際に検索される疑問か。関連語やサジェストも調査する。
- **検索意図:** 読者が知りたいことを具体的に説明できるか。
- **競合状況:** 公式サイトや既存記事で十分に解決されていない点はあるか。
- **独自性:** 独自の整理、わかりやすい説明、比較、具体例を加えられるか。
- **正確性:** 信頼できる根拠を確認できるか。情報の更新が必要か。
- **維持コスト:** 公開後の更新を無理なく続けられるか。
- **BGSとの差別化:** 既存の深掘り記事と検索意図・読者層が重複しすぎないか。
- 「BGSとは」のような用語解説はDisney Discoveryで入口となる基礎を説明し、個別施設の物語や細かな考察はBGS Chroniclesに任せる。

検索ボリュームなどを実測していない段階で「需要が高い」と断定しない。

## 4. 初期候補（調査前の仮案）
以下は採用決定ではなく、検索需要と独自性を調べるための候補。
1. ディズニー公式アプリでできること・基本的な使い方
2. ディズニーに初めて行く前に知っておきたいこと
3. ディズニーのアトラクションはなぜ細部まで作り込まれているのか
4. 東京ディズニーシーのエリアごとに景色が違う理由
5. ディズニーのパークは昼と夜でどう楽しみ方が変わるか
6. BGSとは？ディズニーパークのバックグラウンドストーリーの意味と楽しみ方

公開順や採用記事は、検索語の調査後にユーザーと相談して決める。

## 5. 記事構成の基本
- タイトルで検索者の疑問を具体的に示す
- 初心者向け記事では、誰のどの悩みを解決するかをタイトル・導入で明確にする
- 初心者にしか通じない前提や略語を避け、必要な用語は初出時に短く説明する
- ひとつの記事で複数の初心者向け検索意図を詰め込みすぎず、記事ごとの役割を明確にする
- 冒頭で結論・要点を短く伝える
- 見出しはその節の本文内容と一致させる
- 読者が次に疑問に思いそうな点を、必要に応じて補足する
- 公式情報など一次情報を優先し、重要な主張には出典を示す
- 関連記事への内部リンクは、読者の次の疑問に役立つ場合に設置する
- FAQは実際に想定される疑問がある場合のみ追加する
- 文字数を増やすための重複説明は避ける

## 6. 技術SEO（サイト実装時に確認）
- ページごとに固有で内容に合った title と meta description
- 適切な見出し階層と意味のあるURL
- canonical、XMLサイトマップ、robots.txt
- モバイル表示・表示速度・画像の代替テキスト
- Article等の構造化データは内容と仕様に合う場合のみ使用
- Open Graph / X共有時のタイトル・説明・画像を適切に設定
- Search Console等の計測は、導入時に設定とプライバシー面を確認

## 7. 公開後の改善
検索パフォーマンスを確認できるようになったら、表示回数・クリック率・検索語・順位傾向・記事の鮮度を見て改善する。データがない時点で成果を断定しない。
